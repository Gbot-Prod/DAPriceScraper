API reference

A read-only REST API for daily prevailing retail prices of Philippine food commodities, parsed from the Department of Agriculture's Daily Price Index.

Base URL

Base URL
https://your-host

The basics

  • No authentication. Every REST endpoint is a public GET. CORS allows any origin, so you can call it from browser JavaScript.
  • JSON by default, CSV on request. Price endpoints return CSV when you add ?format=csv or send Accept: text/csv.
  • Prices are decimal strings, like "174.00", so they never pick up floating-point rounding errors. Parse them with a decimal type if you do arithmetic on money.
  • Dates are ISO 8601 (YYYY-MM-DD) and refer to the report date printed on the DA's PDF.
  • Region. Data currently covers the National Capital Region. Endpoints accept region=NCR, which is also the default.

Unofficial project. This API isn't affiliated with the Department of Agriculture. Treat the original DA reports as the authoritative source.

Rate limits

Limits apply per client IP address. /health and the website pages don't count.

WindowRequests allowed
Per minute60
Per hour1,000
Per day5,000

Over the limit, the API returns 429 Too Many Requests with a Retry-After header giving the number of seconds to wait. Prices change once a day, so caching responses on your side (see below) keeps you well within the limits.

Caching

/prices/latest and /prices/summary send an ETag and a Cache-Control header. Send the ETag back in If-None-Match, and if nothing has changed you get an empty 304 Not Modified instead of the full payload.

Conditional request
curl -i "https://your-host/prices/latest" \
  -H 'If-None-Match: W/"3f9a1c0e2b7d4a65"'

# HTTP/1.1 304 Not Modified

Errors

Errors return a JSON body with a detail message:

404 Not Found
{
  "detail": "No report found for date '1999-01-01' in region 'NCR'"
}
StatusMeaning
304Not modified: your cached copy (matched by ETag) is still current.
404Nothing found: unknown commodity ID, a date with no report, or no reports yet for the region.
422Invalid parameter, for example a malformed date or days outside 1–366. detail is a list describing each problem.
429Rate limit exceeded. Wait for the number of seconds in Retry-After.

/prices/summary

JSON

A price band for each commodity over a trailing window: minimum, maximum, median and latest prevailing price, with how many days it was observed. The window ends on the latest report date. One call covers every commodity, so you don't need a history request per item.

ParameterTypeDefaultDescription
daysinteger, 1–36630Length of the trailing window in days.
regionstringNCRRegion code.
commodity_idinteger, repeatableallLimit to specific commodities.

Use it from AI assistants (MCP)

The API also runs an MCP server, so Claude, Cursor, VS Code and other assistants can look up prices for you. Connect it once, then ask in plain language: "How much is local liempo in Metro Manila today?" or "Has the price of red onions gone up this month?"

Server URL

MCP endpoint (Streamable HTTP)
https://your-host/mcp

No sign-up or API key. Calls count toward the same rate limits as the REST API.

Connect your assistant

# claude.ai or the Claude desktop app:
# Settings → Connectors → Add custom connector, then paste this URL
https://your-host/mcp
claude mcp add --transport http dapricescraper https://your-host/mcp
// ~/.cursor/mcp.json
{
  "mcpServers": {
    "dapricescraper": {
      "url": "https://your-host/mcp"
    }
  }
}
// .vscode/mcp.json
{
  "servers": {
    "dapricescraper": {
      "type": "http",
      "url": "https://your-host/mcp"
    }
  }
}

Other MCP clients work too: point any client that supports Streamable HTTP at the URL above. To inspect the tools yourself, run npx @modelcontextprotocol/inspector and connect to the same URL.

Tools

All tools are read-only. Assistants usually start with search_commodities, since the other tools take commodity IDs.

ToolWhat it does
search_commoditiesFind commodities by name, specification or sub-category (e.g. "galunggong") and get their IDs.
list_categoriesBrowse the catalog: categories, sub-categories and how many commodities each has.
get_latest_pricesLatest prevailing price for up to 50 commodities, with the day-over-day change.

get_price_historyDaily prices for one commodity over a date range.
get_report_infoThe DA report a day's prices came from, its checksum and the markets surveyed, for citing sources.

Understanding the data

Prevailing price

The price most commonly observed across the surveyed markets for a commodity on that day, as reported by the DA. It isn't an average.

Unavailable commodities

When the DA reports a commodity as unavailable, the API returns "is_available": false and "price_prevailing": null. The original cell text is kept in raw_price_text. Use available_only=true to leave these out.

Drift flags

Each price is compared with the same commodity's previous price. quality.drift_pct holds the signed change as a fraction, so 0.12 means up 12% and -0.05 means down 5%. It's null when there's no earlier price to compare with. A change of more than 50% either way also sets quality.drift_flagged to true. Flagged prices are kept, not dropped: a flag can mean a real price spike or a typo in the source PDF, so check before relying on it.

Categories

Commodities sit in up to three levels, mirroring the DA's tables: top_category (e.g. LIVESTOCK & POULTRY PRODUCTS), sub_category (e.g. PORK) and group_category. Lower levels are null when the DA doesn't use them.

Stable IDs

A commodity's identity comes from its canonical_key: the normalized category, name, specification and unit. Whitespace or layout changes in the PDF map to the same commodity, so a commodity_id stays valid over time. When the DA renames a commodity outright, the maintainer can link the new name to the original ID with an alias, so its history continues under the same ID.

Self-hosting

One Docker image runs both the API and the scheduled sync job. Point both at the same database.

Shell
git clone https://github.com/Gbot-Prod/DAPriceScraper.git
cd DAPriceScraper
docker build -t da-dpi .

# API, including this website
docker run -p 8000:8000 -e DA_DPI_DB_URL=postgresql://... da-dpi

# Daily sync: run on a schedule (e.g. cron, twice a day)
docker run -e DA_DPI_DB_URL=postgresql://... da-dpi da-dpi run-daily

Without Docker, pip install -e . gives you the da-dpi command: da-dpi sync loads data into SQLite and da-dpi serve starts the API. The README lists every configuration option.
